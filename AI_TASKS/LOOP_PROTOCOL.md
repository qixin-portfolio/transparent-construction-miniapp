# Loop Engineering Protocol

## 目标

Loop Engineering Protocol 用于重复性、可验收、高价值任务。它把工作拆成可重复、可验证、可停止、可追踪、可追责的小循环。

## 什么时候使用 Loop

满足任一条件时使用：

- 任务超过一个阶段。
- 任务会影响多个页面、云函数或数据结构。
- 任务涉及成交闭环、客户管道、AI 能力、素材库等长期模块。
- 任务需要持续审计、设计、开发、验证、复盘。
- 任务有高风险动作，需要 Human Gate。

## Loop 阶段模板

### Phase 0：审计与状态文件

- 只读审计。
- 建立或更新状态文件。
- 不写业务代码。
- 不部署。

### Phase 1：方案与数据结构设计

- 输出模块边界、数据结构草案、风险评估。
- 涉及数据库、云函数、权限时必须 Human Gate。
- 不直接改生产数据。

### Phase 2：Mock 原型

- 使用 mock 数据。
- 不接真实 API。
- 不写生产数据库。
- 可随时删除或停止。

### Phase 3：只读接入

- 只读复用现有数据。
- 不改旧业务逻辑。
- 验证展示和流程价值。

### Phase 4：小范围真实写入

- 新增独立集合或独立云函数优先。
- 写入前必须人工确认。
- 明确回滚方式。

### Phase 5：交付与复盘

- 更新 handoff。
- 更新 PR 描述。
- 记录遗留风险和下一步。

## 停止条件

出现以下情况必须停止并报告：

- 需要部署、上传、迁移、批量操作。
- 需要生产密钥或外部账号权限。
- 需求和现有业务逻辑冲突。
- 无法确定字段、接口或权限规则。
- 检查失败且无法在当前范围内修复。

## Human Gate

Human Gate 必须包含：

- 将要做的动作
- 涉及文件/集合/服务
- 风险
- 回滚方式
- 需要用户确认的问题

未获得确认前，不得继续执行高风险动作。

## 状态文件

每个长期 Loop 任务应在 `AI_TASKS/` 下维护状态文件，建议命名：

`AI_TASKS/<TASK_NAME>_STATE.md`

状态文件至少包含：

1. 项目名称
2. 当前阶段
3. 当前状态
4. 目标
5. 不可破坏约束
6. 已确认模块
7. 暂不做功能
8. 后续阶段计划
9. 当前风险
10. 下一步建议
