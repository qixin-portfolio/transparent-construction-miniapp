# 透明工地小程序 SaaS / V2 成交闭环版：给 Fable5 的产品与技术简报

# 1. 一句话介绍这个项目

这是一个面向装修公司老板、工长、业主的微信小程序 SaaS，最初目标是让装修过程透明化，让业主可以看到工地进度、现场照片、施工日报、设计图确认、售后记录；现在正在扩展 V2 成交闭环能力，帮助装修公司在客户签约前后更好地跟进客户、建立信任、推动成交和交付衔接。

# 2. 项目背景

用户经营的是本地装修公司 / 装修服务相关业务。原始小程序核心是“透明工地”，先解决装修交付过程中的信息不透明和信任问题。

V1 主要服务装修交付过程：

- 客户 / 业主绑定工地
- 工长提交日报
- 老板或管理员审核
- 业主查看施工进度和现场照片
- 设计图确认
- 售后 / 质保记录

V2 现在希望从“交付透明”前移到“成交跟进”：

- 客户还没签约前，老板就能看到客户状态
- 系统给出跟进建议
- 帮助销售解释透明工地、信任证据、案例、施工过程
- 签约后再衔接到真实工地管理

# 3. 当前产品分层

## V1：透明工地交付系统

V1 的主要价值是让装修交付过程被记录、被审核、被业主看见。

主要价值：

- 让业主不用天天跑工地，也能看施工进度
- 工长按节点提交日报和照片
- 老板审核后业主可见
- 工地过程留痕
- 减少装修过程中的不信任
- 方便装修公司展示专业度

主要角色：

1. 老板 / 管理员

   - 看客户
   - 看工地
   - 审核日报
   - 管理项目
   - 管理设计图、售后等

2. 工长

   - 提交施工日报
   - 上传现场照片
   - 汇报施工节点

3. 业主

   - 查看自己的工地
   - 查看进度、照片、设计方案
   - 确认部分信息

4. 销售 / 内部人员

   - 现阶段不是 V2 入口开放对象
   - 后续可能扩展销售跟进能力

## V2：成交闭环 / 成交跟进系统

V2 是一个老板内部试验功能，不是正式发布功能。它尝试把透明工地的信任价值前移到成交阶段，让老板在客户成交前就能看到客户线索、跟进状态、下一步动作、信任材料、话术建议、签约后转工地草案等。

V2 当前重点不是“自动成交”，而是帮助老板更快判断“这个客户下一步该怎么跟”。

# 4. 当前 V2 页面结构

V2 子包路径：

```text
miniprogram/subpackages/deal-loop/
```

当前页面包括：

1. `pipeline`

   - 客户成交跟进列表
   - 展示客户阶段、意向、跟进状态
   - 当前新增“销售下一步动作卡”
   - 展示下一步动作、跟进重点、提示
   - 本地规则生成，不是真实 AI
   - 不写库、不改客户状态

2. `customer-detail`

   - 客户成交详情页
   - 展示客户基本信息
   - 展示成交跟进复盘
   - 展示下一步跟进动作
   - 展示当前判断、建议动作、复制跟进话术
   - 复制只使用 `wx.setClipboardData`
   - 不发送消息、不写跟进记录

3. `ai-assistant`

   - 早期 AI 助手雏形
   - 当前主要是基于真实客户字段 + 本地示例建议
   - 不调用真实 AI API
   - 不应被理解为正式 AI 自动成交工具

4. `trust-materials`

   - 信任材料页
   - 已接入 `getV2EvidenceSummary` 云函数
   - 只读汇总真实客户 / 工地证据
   - 展示可用证据类型，例如已审核日报、可见照片、设计图、质保卡等
   - 不展示隐私原始文件
   - 不自动发布案例

5. `contract-to-project`

   - 签约转工地草案页
   - 当前只生成草案
   - 不调用 `createProject`
   - 不创建真实工地

6. `case-assets`

   - 案例资产草案页
   - 当前只生成内部参考内容
   - 不自动发布案例
   - 不对外宣传

# 5. V1 工作流详细介绍

## 5.1 创建客户 / 项目

装修公司内部先录入客户。客户可能对应一个或多个工地项目。项目包含业主、地址、装修阶段、施工状态等信息。

这一步是 V1 交付链路的起点：先有客户和工地，后续日报、审核、业主查看都围绕这个工地展开。

## 5.2 工地施工日报

工长进入小程序，选择对应工地，填写今日施工内容，上传现场照片，然后提交日报。

日报的价值不是写给系统看，而是把每天的施工情况沉淀下来，形成可追溯的工地过程记录。

## 5.3 老板 / 管理员审核

老板或管理员看到待审核日报后，判断内容是否适合给业主看。

通过后，业主可见；不通过，则需要内部修改。这个审核机制可以避免未经筛选的信息直接暴露给业主，也让装修公司保留管理口径。

## 5.4 业主查看

业主进入小程序后，只能看到自己绑定的工地。

业主可以查看施工进度、日报、现场照片，也可以看到设计图、确认记录、售后信息等。

## 5.5 信任建立

装修过程被记录后，业主会更放心。老板也可以把“透明工地”作为成交卖点。

长期看，这些施工日报、照片、设计图、质保记录也可能沉淀成案例资产和销售证据。

# 6. V2 成交闭环工作流详细介绍

## 6.1 客户进入 pipeline

客户从原有客户系统进入 V2 成交跟进列表。

pipeline 里老板看到：

- 客户是谁
- 当前阶段
- 意向程度
- 预算 / 需求 / 房屋信息
- 下一步动作
- 跟进重点
- 风险或机会提示

## 6.2 老板判断下一步怎么跟

系统根据本地规则给出内部参考：

- 新客户：先补齐需求信息
- 已沟通 / 已量房：确认方案、预算、顾虑
- 已报价：24 小时内回访，拆解价格顾虑
- 高意向：准备信任证据
- 有顾虑：解释透明工地和施工留痕
- 已签约：整理工地创建草案，但不创建真实工地

这些不是 AI 自动判断，只是内部参考规则，需要人工判断。

## 6.3 进入 customer-detail

老板点击客户详情后，可以看到：

- 当前跟进判断
- 3 条建议动作
- 阶段化复制跟进话术
- 成交跟进复盘问题

用途是帮助老板或销售更快组织沟通，而不是替人自动成交。

## 6.4 复制跟进话术

老板可以点击复制话术。

当前能力边界：

- 只复制到剪贴板
- 不自动发送微信
- 不写入跟进记录
- 不改变客户状态
- 不请求接口
- 不调用真实 AI

## 6.5 信任材料补充

当客户顾虑较强时，老板可以进入 `trust-materials`，看当前客户或项目有哪些可信证据。

例如：

- 已审核施工日报
- 可见现场照片
- 设计图
- 授权案例
- 质保记录

用途是把“我们施工透明、过程留痕、可看工地”变成成交阶段的信任材料。

## 6.6 签约后转工地草案

客户签约后，`contract-to-project` 可以生成工地创建草案。

当前边界：

- 只生成草案
- 不创建真实工地
- 不调用 `createProject`
- 不写数据库

未来方向：

- 如果验证通过，可以设计人工确认后创建真实工地

## 6.7 案例资产草案

`case-assets` 可以基于客户和工地信息生成案例内容草案。

当前边界：

- 只做内部参考
- 不自动发布
- 不生成对外承诺
- 不直接作为营销内容上线

未来方向：

- 和案例授权、施工过程证据、业主评价打通后，形成可控案例资产

# 10. 产品核心假设

假设 1：

装修公司老板不是缺“系统”，而是缺一个能告诉他“这个客户下一步该怎么跟”的工具。

假设 2：

透明工地的价值不只在交付阶段，也可以前移到成交阶段，作为信任卖点。

假设 3：

装修成交的关键不是自动化，而是降低客户不信任：

- 怕施工不透明
- 怕材料不清楚
- 怕报价有坑
- 怕后期没人管
- 怕踩坑

假设 4：

小程序如果能把客户顾虑、信任证据、跟进话术、签约后交付衔接串起来，就可能从“工地查看工具”升级成“装修公司成交与交付一体化 SaaS”。
