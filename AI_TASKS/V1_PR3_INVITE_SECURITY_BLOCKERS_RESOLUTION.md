## 2. 二次审查阻塞项

Phase 7-SEC-4 确认两个 P1：

1. 失败计数只按 `openid + code`，攻击者可通过每次更换六位数字绕过锁定。
2. 邀请码生成采用先查询再新增，仓库无法证明并发情况下 code 唯一。

## 3. 调用者全局限流

现在同时维护两个哈希限流键：

- 调用者全局键：只基于 openid，同一调用者尝试不同 code 也会累计。
- 具体邀请码键：基于 openid + code，保留单个 code 维度追踪。

两个键在同一个数据库事务中读取、累计和写回。任一键达到 5 次后锁定 15 分钟。成功兑换后在兑换事务中同时清零两个键。

## 4. 邀请码原子唯一生成

新邀请码使用六位 code 作为 `staff_invite_codes` 文档 `_id`：

1. 在事务内读取 code 对应的文档 ID。
2. 同时查询历史随机文档 ID 中是否已经存在同 code 记录。
3. 任一记录存在即返回 `INVITE_CODE_COLLISION`。
4. 不存在时在同一事务中以 code 为文档 ID 写入。
5. 并发事务竞争同一文档 ID 时只能有一个成功；失败请求重新生成新 code，最多尝试 12 次。

该方案不新增数据库集合，也不依赖控制台唯一索引。历史邀请码仍可按原记录兑换，新代码不会复用历史已使用、撤销或过期的 code。

## 5. 行为测试

新增或加强：

- 相同 code 的两个租户并发占位只能一个成功。
- 历史随机文档 ID 中存在同 code 时拒绝占位。
- 首次 code 冲突后自动生成下一 code。
- 同一调用者连续尝试不同 code 仍会在第 5 次后锁定。
- 相同 code 的并发失败次数继续原子累计。
- 成功兑换同时清空调用者全局和具体 code 计数。

完整测试结果：

- 静态安全回归：20/20。
- 行为测试：43/43。
- 合计：63/63。

行为测试使用受控 fake transaction，不替代真实 CloudBase 事务测试。
