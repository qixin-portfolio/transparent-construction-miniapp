## V2 六页能力边界复查

### 1. pipeline

复查结论：适合继续保持只读内部评审，不建议直接开放给真实业务人员。

当前页面表达：

1. `V2 试验功能 / 只读客户资料 / 不影响现有数据`。
2. 仅用于内部成交跟进。
3. 不修改现有客户数据。
4. 客户列表读取失败时展示示例内容。

能力边界：

1. 只读展示客户资料。
2. 不写入客户数据。
3. 不创建客户、不修改客户阶段。

主要风险：

1. 销售可能误以为这是正式客户工作台。
2. 示例内容和真实客户资料混用时，需要继续保持清晰提示。

### 2. customer-detail

复查结论：文案已收口为只读客户资料，但仍建议仅限内部小范围体验。

当前页面表达：

1. `客户成交详情`。
2. `只读客户资料`。
3. `示例跟进记录`。
4. 当前为示例建议，不调用真实 AI。
5. 仅用于内部成交跟进，未修改任何数据。

能力边界：

1. 只读客户资料。
2. 不写客户跟进记录。
3. 不修改客户数据。
4. 示例跟进记录已明确为示例。

主要风险：

1. 真实客户详情与示例跟进记录同页出现，销售可能误认为跟进记录来自真实业务系统。
2. 后续若开放给普通销售，需要再确认角色和数据权限。

### 3. ai-assistant

复查结论：Phase 5C-J 已修复阶段码展示，当前适合继续内部验证，不适合对外宣称真实 AI。

当前页面表达：

1. `AI 跟进助手`。
2. `示例建议 / 内部参考`。
3. 当前仅根据客户阶段生成跟进建议，不调用真实 AI。
4. 数据源为只读客户资料。
5. 阶段码已中文化，例如 `quoted / signed` 已映射为中文业务文案。

能力边界：

1. 不调用真实 AI。
2. 仅输出示例建议或规则建议。
3. 不写入客户跟进记录。
4. 不调用新增 AI API。

主要风险：

1. 销售可能把示例建议当成真实 AI 结论。
2. 页面名称含“AI”，即使已有“不调用真实 AI”说明，仍可能造成能力预期偏差。

### 4. trust-materials

复查结论：真实证据摘要边界已清楚，但公开授权风险仍是入口打开前重点。

当前页面表达：

1. `真实证据摘要`。
2. `示例推荐素材`。
3. 只读客户资料。
4. 不展示原始照片和日报正文。
5. 公开使用需先确认授权。
6. 内部成交跟进，不影响现有客户、工地和日报数据。

能力边界：

1. 只读真实证据摘要。
2. 不展示原始照片、文件地址、日报正文和个人隐私。
3. 不直接生成公开案例。
4. 未授权时仅内部参考。

主要风险：

1. 老板或销售可能误认为证据摘要可以直接公开使用。
2. 公开授权与内部跟进之间仍需要人工判断。
3. 错误态虽已文案收口，但仍建议继续做真实设备场景覆盖。

### 5. contract-to-project

复查结论：页面已明确为草案预览，当前不能作为真实创建工地入口。

当前页面表达：

1. `签约转工地草案`。
2. `草案预览`。
3. 当前仅为草案预览，不会创建真实工地。
4. 不影响现有项目数据。
5. 不修改现有项目数据。

能力边界：

1. 不调用 `createProject`。
2. 不写 `projects`。
3. 不创建真实工地。
4. 仅预览工地草案字段。

主要风险：

1. 老板或销售可能误认为点击后会创建真实工地。
2. 如果未来加入创建能力，必须单独进入高风险阶段和 Human Gate。

### 6. case-assets

复查结论：页面已明确为案例内容草案，但公开发布误解风险仍需强控制。

当前页面表达：

1. `案例内容草案`。
2. `示例草案 / 内部参考 / 需授权`。
3. 当前仅整理内容方向，不代表已获得公开发布授权。
4. 不支持自动发布。
5. 公开使用需先确认授权。
6. 不写数据库。

能力边界：

1. 仅生成案例内容草案。
2. 不支持自动发布到小红书、抖音、官网或 GEO。
3. 不调用发布服务。
4. 不修改真实授权记录。

主要风险：

1. 老板可能误认为案例内容可以直接发布。
2. 销售可能将草案当成已授权公开素材。
3. 后续如接入真实案例授权，需要单独做权限与授权链路评审。

## 权限与角色风险

当前入口权限判断：

1. 开关为 `ENABLE_V2_DEAL_LOOP_ENTRY`。
2. 角色门槛为 `admin / boss_qi / boss_hu`。
3. 普通销售、设计师、工长、业主当前不会通过工作台看到入口。

风险判断：

2. 若打开入口，仅靠 boss/admin 角色仍偏粗，建议增加明确体验账号范围。
3. 不建议向普通销售开放，除非先完成销售使用边界和话术培训。
4. 不应对业主端、工长端开放。
5. 不应将入口放入 tabBar 或任何高频主入口。

## 有限内部体验前置条件

如果未来要打开入口，建议至少满足以下前置条件：

1. 只对老板账号开放，优先 `boss_qi / boss_hu`，暂不对普通销售开放。
2. 入口继续显示 `V2 试验功能`。
3. 不对业主端开放。
4. 不对工长端开放。
5. 不对普通销售开放，除非单独确认体验范围和培训口径。
6. 不上传正式版。
7. 首次只做微信开发者工具或内部体验版验证。
8. 明确体验时间窗口，例如 1 到 3 天。
9. 明确体验目标：只看页面理解度、文案风险和边界提示，不验证正式成交效果。
10. 保留一键关闭方式：`ENABLE_V2_DEAL_LOOP_ENTRY = false`。
11. 发现问题立即关闭入口，并回滚到当前安全 tag。
12. 入口打开前再次确认不会写数据库、不会创建真实工地、不会调用真实 AI、不会自动发布。
13. 入口打开前准备老板/体验者说明，明确“内部试验，不代表正式功能”。

## 回滚方案

当前安全 tag：

`v2-deal-loop-phase5c-k-manual-screenshot-acceptance`

建议回滚策略：

1. 如果只是入口体验风险，优先关闭入口：将 `ENABLE_V2_DEAL_LOOP_ENTRY` 恢复或保持为 `false`。
2. 如果入口打开后代码出现异常，回滚到安全 tag：`v2-deal-loop-phase5c-k-manual-screenshot-acceptance`。
3. 如果未来已经上传体验版，关闭入口后需要重新上传新的体验版覆盖旧包；当前阶段未上传体验版。
4. 入口关闭不需要重新部署云函数。
5. 当前 V2 不写客户、工地和日报数据，因此回滚不应丢失 V1 真实业务数据。
6. 不能回滚丢失的内容包括：用户已经看到或截图传播的试验页面认知，因此体验前必须控制账号、范围和时间窗口。
7. 如果未来引入真实写入、真实 AI 或创建工地能力，必须重新设计更严格的回滚和数据修复方案。
